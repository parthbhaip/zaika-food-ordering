### Gotchas
- Thymeleaf 3.1 restricted mode: no bean calls (`@x...`) or `param` inside `th:href`/`th:src`; compute in `th:with`. `<th:block th:each>` around a `th:replace`, never both on one tag. Inside `th:object`, `*{...}` cannot see loop variables (use `${form.x}`). A fragment-expression string literal cannot contain `\'`. Use `~{template :: frag(...)}` with the explicit template name inside layout pages. Thymeleaf escapes `'` as `&#39;` and wraps attributes (squash whitespace before asserting). Do not name a boolean `isX()` that clashes with a property `x` on a form.
- MockMvc: `get(String)` re-encodes `%` and never decodes `+`; use `get(URI.create(url))` with `%20`. Security 7 redirects to the relative `/login`. `formLogin()` lacks `.param()`: post `/login` with `csrf()`. Flash set by Security handlers is invisible to `flash()`; assert on the rendered page. MockMvc does not forward `sendError` to `/error`.
- Hibernate: an entity rejected by Bean Validation stays in the session without an id; `em.clear()` before continuing.
- H2 auto-indexes every FK, so index tests check index names (`information_schema`), not columns. Every page creates a session (CSRF meta), so test "no guest cart stored", not "no session".
- Never write a raw NUL or other control byte into a source file (git treats it as binary); use `\0` escapes.
- `commandfor`/`command` dialogs need very recent browsers; menus use `<details>` instead.

## T19 Cart domain (2026-10-05)
- Recovered: an earlier iteration was cut off after writing the `cart` package, `V7__create_carts.sql` and two `MenuItemRepository` entity-graph finders; kept and finished them. `V7`: `carts` (unique `user_id`, one cart per customer), `cart_items` (unique (cart_id, menu_item_id), `idx_cart_items_menu_item`, CHECK quantity 1-20, `unit_price` = the price the customer last saw).
- `cart.CartService` holds every rule for both stores behind `CartContents`: `Cart` (entity, signed-in customers) and `GuestCart` (session attribute `GuestCart.SESSION_KEY`, Serializable, synchronized). `CartOwner.of(request, create)` = `Customer(userId)` (principal must be `CurrentUser`), `Guest(cart)` for anonymous visitors, or `null` for staff (no cart -> 403). `setQuantity(owner, itemId, qty, startNew)` takes an absolute quantity (0 removes, >20 capped with `capped`), returns `CartChange` (ADDED, UPDATED, REMOVED, UNCHANGED, SOLD_OUT, CLOSED, OTHER_RESTAURANT); raising a quantity needs the dish available and the kitchen accepting orders and within hours, lowering always works. Archived dishes / unapproved kitchens -> 404. Customer changes lock the `users` row (`findForUpdate`), so a double-tapped ADD is serialized.
- `view(owner)` = `CartView` re-checked on every call: sold-out or archived/deleted dishes are removed, a kitchen that is no longer APPROVED empties the cart, new prices replace the remembered one; each change becomes a one-time notice. `itemTotal` is the plain sum; T20's `PriceBreakdown` should take `CartView` (restaurant + itemTotal) as its input.
