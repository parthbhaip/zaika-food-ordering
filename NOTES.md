## T10 Forgot and reset password (2026-10-05)
- `user.PasswordResetService` + `PasswordResetToken` (`V3__create_password_reset_tokens.sql`: unique `token_hash`, FK `ON DELETE CASCADE`, `idx_password_reset_tokens_user`). Token = 32 `SecureRandom` bytes, base64url (43 chars) in the link; only its SHA-256 hex is stored. Valid for `LINK_LIFETIME` 30 min, only for enabled accounts. A reset takes a row lock on the token (`findForUpdateByTokenHash`), sets the hash via `User.resetPassword` (also clears `failedLoginCount`/`lockedUntil`, so T11 locks are lifted by a reset) and spends every open link of the account (`markAllUsed`, bulk JPQL update). Several links can be open at once (a second "send again" does not kill the first). Expired rows are not purged (nothing reads them).
- Routes (`user.PasswordResetController`, both already public in `SecurityConfig`): GET/POST `/forgot-password` (`ForgotPasswordForm`; always redirects back with flash `sentTo` -> "Check your inbox", identical for unknown/disabled emails, proven byte-for-byte minus CSRF tokens in `PasswordResetPageTest`), GET `/reset-password?token=` (form, or `linkExpired` state with "Send a new link"), POST `/reset-password` (`PasswordResetForm`, token in a hidden field, `RegistrationForm.checkNewPassword`; success -> `/login` with flash `email` prefilled and a toast). Templates `auth/forgot-password.html` (also holds the shared `safety` aside fragment) and `auth/reset-password.html`.
- Mail: `notification.MailService.send(to, subject, text)`. `LoggingMailService` (`app.mail.log-only=true`, dev + test) logs the whole body, so the reset link appears in the dev log, as PLAN asks; it never runs in mysql. `SmtpMailService` (otherwise) sends a `SimpleMailMessage` from `app.mail.from` (env `MAIL_FROM`) and is `@Async` (`@EnableAsync` on `ZaikaApplication`), so unknown and known emails answer equally fast and the page never waits for SMTP. The old `LoggingMailSender` (a fake `JavaMailSender`) is deleted: dev/test now have no `JavaMailSender` bean, so later code must use `MailService`, never `JavaMailSender` directly. `ZaikaApplicationTests`/`DevProfileTest` were changed accordingly (the old "body is not logged" assertion is now "body is logged", by T10's requirement).
- Links in emails use the new `AppProperties.baseUrl` (`app.base-url`, env `APP_BASE_URL`, default `http://localhost:8080`, trailing slash dropped, must be http(s)), never the request's Host header (reset-link poisoning). Later emails (T39, T45) should build links from it too.
- Tests read the raw token from the captured log (`PasswordResetServiceTest.lastToken(CapturedOutput)`, reusable from other tests in `com.zaika.user`). Not checked visually in a browser (no server allowed). T55: rate-limit POST `/forgot-password` (per IP and per email) and wrong reset attempts; the concurrent double-submit path relies on the pessimistic lock and is not covered by a concurrent test.
